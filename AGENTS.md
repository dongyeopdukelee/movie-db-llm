# Project instructions

Before proposing, implementing, or changing product scope, architecture, or
technology, read `docs/decisions.md`.

Treat it as the current source of truth for high-level project decisions.
Update it when a decision is made, changed, or removed.

# Testing

Keep tests aligned with the product: when behavior is added, changed, or
removed, add, update, or remove the relevant tests in the same change. Cover
user-visible API flows end-to-end where practical, and use focused unit tests
for isolated logic.
